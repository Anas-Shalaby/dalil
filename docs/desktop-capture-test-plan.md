# خطة الاختبار اليدوي — التقاط من الكمبيوتر

هذه الخطة تختبر السلوك الحقيقي لـ `chrome.desktopCapture` داخل Chrome عادي. لا يمكن محاكاة نافذة اختيار المصدر أو بث سطح المكتب الحقيقي في بيئة الاختبارات الآلية، لذلك تبقى هذه البنود **يدوية** ولا تُعتبر ناجحة حتى تُنفَّذ فعليًا.

> الحالة في هذا التسليم: **لم تُنفَّذ اختبارات سطح المكتب اليدوية** داخل بيئة التطوير الحالية. الاختبارات الآلية غطّت منطق الجلسة والالتقاط والتخزين بواجهات محاكاة، لكنها لا تثبت عمل نافذة Chrome الحقيقية.

---

## 1. التجهيز

1. نفّذ:
   ```bash
   npm install
   npm run typecheck
   npm test
   npm run build
   ```
2. افتح `chrome://extensions`.
3. فعّل **وضع المطوّر**.
4. اضغط **Load unpacked** واختر مجلد `dist`.
5. تأكد أن الإضافة لا تعرض أخطاء Manifest، وأن صلاحية `desktopCapture` مذكورة في بطاقة الإضافة.
6. جهّز تطبيق سطح مكتب بسيط للتوثيق (مثل تطبيق Notes أو آلة حاسبة) في نافذة منفصلة.
7. افتح DevTools للإضافة (زر **service worker** ثم Console) وراقب أي أخطاء أثناء الجلسة.
8. افتح تبويبًا آخر على `chrome-extension://<id>/capture.html` لتجهيز اختبار التعارض لاحقًا عند الحاجة، ثم أغلقه.

## 2. حالات الاختبار

| # | الحالة | الخطوات | النتيجة المتوقعة | النتيجة الفعلية |
| --- | --- | --- | --- | --- |
| D1 | فتح صفحة الالتقاط من النافذة المنبثقة | افتح النافذة المنبثقة ← **التقاط من الكمبيوتر** | يُفتح تبويب `capture.html` بحالة `idle`، ويظهر شرح تفضيل «نافذة البرنامج» |  |
| D2 | إلغاء اختيار المصدر | اضغط **اختيار نافذة أو شاشة** ثم **إلغاء** في نافذة Chrome | تعود الحالة إلى `idle` مع رسالة «لم يتم اختيار نافذة أو شاشة»، ولا يبقى زر الاختيار معلّقًا |  |
| D3 | اختيار نافذة برنامج | اضغط **اختيار نافذة أو شاشة** ← اختر نافذة تطبيق Notes | تنتقل الحالة إلى `recording`، ويظهر «الالتقاط جاهز» وزر **التقاط خطوة** |  |
| D4 | التقاط خطوة واحدة | اضغط **التقاط خطوة** | تُضاف خطوة واحدة بلقطة، يزيد عدّاد الخطوات، ويظهر مؤشر حفظ |  |
| D5 | وضوح النص | افتح اللقطة في المحرر ثم في معاينة الطباعة | نص واجهة البرنامج مقروء على الشاشة وعلى A4 |  |
| D6 | خطوات متعددة | غيّر محتوى النافذة ثم التقط 3 خطوات | ثلاث خطوات مستقلة، كل واحدة بلقطة مطابقة للحظة الضغط |  |
| D7 | منع المصدر المزدوج | أثناء `recording` لا يظهر زر اختيار مصدر جديد | لا يمكن فتح مصدرين متزامنين من نفس الصفحة |  |
| D8 | إيقاف المصدر | اضغط **إيقاف الالتقاط** | تتوقف اللقطات، تعود الحالة `idle`، وتبقى الخطوات السابقة |  |
| D9 | إعادة اختيار المصدر | بعد D8 اضغط **اختيار نافذة أو شاشة** واختر نافذة أخرى | يعمل مصدر جديد، والخطوات القديمة تبقى |  |
| D10 | إنهاء المصدر من Chrome | أثناء `recording` أغلق نافذة البرنامج أو اضغط «إيقاف المشاركة» إن ظهر | تظهر رسالة «انتهى مصدر الالتقاط»، تُحفظ الخطوات، ولا يمكن الالتقاط بعدها |  |
| D11 | منع الالتقاط بعد التوقف | بعد D8 أو D10 حاول الضغط على مساحة الالتقاط أو زر معطّل | لا تُضاف أي خطوة ولا تُلتقط صورة |  |
| D12 | حذف خطوة | اضغط حذف على خطوة وأكّد | تُحذف الخطوة ولقطتها، وتُعاد ترقيم الباقي |  |
| D13 | تحرير الوصف | اكتب وصفًا لخطوة ثم انتقل لعنصر آخر | يُحفظ تلقائيًا ويظهر «تم الحفظ» |  |
| D14 | إنهاء الجلسة | اضغط **إنهاء التوثيق وفتح المحرر** | يُفتح المحرر بالدليل نفسه مع كل الخطوات واللقطات |  |
| D15 | التوضيحات | من المحرر اضغط **تعديل الصورة** وأضف سهمًا ونصًا | يظهر التوضيح في المحرر والطباعة |  |
| D16 | الطباعة PDF | من المحرر اضغط **طباعة / حفظ PDF** ثم احفظ PDF | PDF عربي RTL يحتوي الخطوات ولقطات سطح المكتب |  |
| D17 | الاستمرارية | أغلق Chrome وأعد فتحه ثم افتح **أدلتي** | الدليل موجود، وشارة «الكمبيوتر» تظهر عليه، واللقطات سليمة |  |
| D18 | تعارض جلستين | افتح جلسة نشطة، ثم افتح `capture.html` في تبويب ثانٍ | تظهر رسالة «جلسة التقاط أخرى مفتوحة»، وزر للعودة إلى الجلسة الحالية، ولا يبدأ التقاط ثانٍ |  |
| D19 | تحرير القفل بإغلاق التبويب | أغلق تبويب الجلسة الأولى ثم أعد فتح جلسة جديدة | لا تظهر رسالة تعارض، ويمكن البدء مباشرة |  |
| D20 | الشاشة الكاملة | اختر **الشاشة الكاملة** والتقط خطوة | تعمل اللقطة، ومن المتوقع ظهور واجهة دليل نفسها إن كانت في المقدمة |  |
| D21 | نافذة محمية/سوداء | حاول اختيار نافذة يمنعها النظام أو محتوى محمي | لا تُدّعى النجاح؛ تظهر رسالة عربية مناسبة، أو لقطة سوداء مع إمكانية الحذف |  |
| D22 | لا شبكة | راقب DevTools ← Network أثناء الجلسة كلها | لا توجد طلبات شبكة |  |
| D23 | إغلاق الصفحة أثناء الجلسة | أغلق تبويب `capture.html` أثناء `recording` | يتوقف البث، وتُحرَّر الجلسة، والخطوات المحفوظة تبقى في الأدلة |  |

## 4. معايير القبول

- كل بنود D1–D23 الحرجة ناجحة في Chrome عادي.
- لا أخطاء غير معالجة في Console أثناء الجلسة.
- لا التقاط بعد التوقف أو بعد انتهاء المصدر.
- لا يمكن تشغيل جلستين متزامنتين.
- كل الرسائل الظاهرة للمستخدم عربية، والتفاصيل التقنية تبقى في Console فقط.
- الصور تُحفظ محليًا فقط، والتصدير PDF يعمل من صفحة الطباعة الأصلية.

---

## 5. القيود المعروفة مسبقًا

- نافذة اختيار المصدر من Chrome، ولا يمكن تخصيص شكلها أو تجاوزها برمجيًا.
- لا يوجد اختصار لوحة مفاتيح عام ولا طبقة عائمة فوق التطبيقات الأخرى.
- الشاشة الكاملة قد تتضمن واجهة دليل نفسها.
- بعض النوافذ المحمية لا يمكن التقاطها بحسب سياسة النظام/Chrome.
- جلسة واحدة فقط في كل مرة، والتبويب المغلق يحرر القفل.
